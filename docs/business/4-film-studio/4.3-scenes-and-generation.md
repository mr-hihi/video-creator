# 4.3 Scenes & generation

Part of [4. Film Studio](../4-film-studio.md). A scene owns one still image, one clip made from that image
and one narration. Each is produced by a `GenerationRequest` that a dedicated worker hands to a provider.

## Data model — `Scene` (table `film_scenes`)

| Field | Type | Meaning |
|---|---|---|
| `id` | string(36) | UUID v4 |
| `episode_id` | string(36) | → `film_episodes.id`; deleted with the episode |
| `position` | int | 0, 1, 2 … without gaps; shown as `Scene {position + 1}` |
| `image_prompt` | text | 1–4000 characters; what the still shows — action and setting, not the characters' looks |
| `video_prompt` | text | 1–4000 characters; timed beats (`0-3s: … 3-6s: …`), camera, lighting, sound |
| `narrator_text` | text \| null | at most 1000 characters |
| `character_ids` | JSON | ids of linked characters shown in the scene; their references are sent with the image |
| `clip_duration_s` | int | 4–30 — the length of the scene's clip; from the script (4.2), else the project's `clip_duration_s` (4.1) |
| `image_status` / `clip_status` / `narration_status` | enum | `none` \| `queued` \| `processing` \| `done` \| `failed` |
| `image_source` | enum \| null | `generated` \| `edited` \| `uploaded` \| `film_clone` |
| `image_path` / `clip_path` / `narration_path` | string \| null | files below |
| `image_error` / `clip_error` / `narration_error` | text \| null | the last failure |
| `clip_duration_ms` / `narration_duration_ms` | int \| null | from `ffprobe` |
| `trim_start_ms` | int | default `1000` — the first second of a clip is often a still frame |
| `trim_end_ms` | int \| null | `null` = the clip's end |
| `provider_media` | JSON \| null | provider-side ids of the image and clip, written by providers |
| `created_at` / `updated_at` | datetime (UTC) | |

Files: `storage/films/projects/{project-id}/episodes/{episode-id}/scenes/{scene-id}/` holds `image.{ext}`,
`clip.mp4` and `narration.{ext}`. A new file replaces the old one. A clip made in segments keeps them in
`clip-segments/` until it is joined (§ Segments).

## Data model — `GenerationRequest` (table `film_generation_requests`)

| Field | Type | Meaning |
|---|---|---|
| `id` | string(36) | UUID v4 |
| `kind` | enum | `character_image` \| `scene_image` \| `edit_image` \| `scene_clip` \| `narration` \| `music` \| `thumbnail` \| `clone_reference_image` \| `clone_scene_image` |
| `media_kind` | enum | `image` \| `edit_image` \| `video` \| `speech` \| `music` (4 § Media providers) |
| `project_id` | string(36) \| null | deleted with the project; `null` for a Film Clone request |
| `clone_id` | string(36) \| null | the film clone (domain 5); deleted with the clone |
| `episode_id` / `scene_id` / `character_id` / `clone_asset_id` / `clone_scene_id` | string(36) \| null | the target; `edit_image` targets a scene or a character |
| `provider` | string(20) | → `providers.id` (7.1), picked at creation from the image or clip provider setting of Film Studio or Film Clone (6.1), or the `image` / `video` route (7.2) when it is `null`; fixed afterwards |
| `prompt` | text | the prompt as sent (below) |
| `input_paths` | JSON | files sent: start image, references, source image, voice sample |
| `params` | JSON | aspect, clip length, segment progress (7.1), language, minimum length, thumbnail candidate |
| `status` | enum | `queued` \| `processing` \| `done` \| `failed` \| `cancelled` |
| `external_id` | string \| null | the provider's operation id once submitted |
| `attempts` | int | counted attempts |
| `next_attempt_at` | datetime \| null | earliest next try |
| `output_path` | string \| null | where the result was saved |
| `error_message` | text \| null | set when `failed` |
| `created_at` / `started_at` / `finished_at` | datetime (UTC) | |

### Target status

| Request | Target |
|---|---|
| created | `queued` |
| `processing` | `processing` |
| `done` | `done`; file saved, duration read; the downstream resets below apply |
| `failed`, target had no file | `failed` with the error |
| `failed` or `cancelled`, target had a file (a regenerate) | back to `done` with its old file; the error is kept on the target |
| `cancelled`, target had no file | `none` |

The target of a clone request is the asset's reference (5.3) or the scene's image (5.4).

## Worker

- A loop inside the API process, separate from the job worker of 1.1, runs every
  `FILM_WORKER_POLL_INTERVAL_SEC`. Stopping the API stops it.
- It claims the oldest `queued` request whose `next_attempt_at` has passed, whose provider has a free
  slot (`max_concurrent` and `min_interval_s` of the provider, 7.1) and whose dependency below holds.
- It submits the request, stores `external_id`, polls until the provider answers, and downloads the
  result at once — provider links expire — to the target's file path.
- Requests of every episode, project and film clone share the queue, oldest first per provider.
- Each time a request becomes final, the stage of its episode is checked (4.2 § Stages), or the step of its
  film clone (5.1).

### Retries

| Provider answer | Handling |
|---|---|
| Input media expired or not found on the provider's side | inputs uploaded again, retried, not counted |
| Extension disconnected, reconnected or not connected | back to `queued`, not counted |
| `extension_hijack_detected` | back to `queued`, not counted |
| Other captcha failure | retried until 10 attempts, then `failed` |
| Google `unusual activity` | `failed` at once; the Google Flow provider pauses for 120 s |
| Capability unsupported, or no Flow project | `failed` at once |
| Provider not set up, narrator voice short of the provider's needs (7.1) | `failed` at once with the message of 7.1; nothing is sent |
| Blocked by the content filter | `failed` at once — the same prompt gets the same answer |
| HTTP 5xx or 429 when sending | retried until `FILM_REQUEST_MAX_ATTEMPTS` attempts, waiting min(2ⁿ × 10 s, 300 s) |
| Other Google Flow failures (no token, an error code, an empty answer) | retried as a 5xx |
| No answer in time (Google Flow: 300 s), or the provider cannot be reached, when sending | `failed` at once — the provider may have taken the work, and a second submit is paid again |
| A status check that times out, cannot connect or gets a 5xx / 429 | asked again at the next poll — never submitted again |
| No result after 1800 s of polling | `failed` |
| Anything else | `failed` at once |

API restart: a `processing` request with an `external_id` keeps polling and is never submitted again — a
second submit is paid again. One without an `external_id` returns to `queued`, not counted.

### Cancel

`POST /films/requests/{id}/cancel` cancels one `queued` Film Studio request — the way out of a request that
would wait forever, such as a Google Flow request while no extension is connected.

| Rule | Result |
|---|---|
| Unknown request, or a Film Clone request | 404 `Generation request {id} not found` |
| Status other than `queued` | 409 `Only a queued request can be cancelled` |
| Its episode is `running`; for a request with no episode (a character image), any episode of its project is `running` | 409 `Episode {number} is running — stop it first` |
| Otherwise | `cancelled`, the target as in § Target status; answers the request |

## Prompts sent

| `kind` | Prompt | Inputs | Params |
|---|---|---|---|
| `character_image` | the character's `image_prompt` | — | aspect of its `entity_type` (4.1) |
| `scene_image` | `{scene_prefix} {image_prompt}` (`scene_prefix` of the project's style, when set) | references of `character_ids` | project aspect |
| `edit_image` | the edit prompt | the current image; for a scene also the references of `character_ids` | aspect of the current image |
| `scene_clip` | the clip prompt below | the scene image as start frame; segments: § Segments | the scene's `clip_duration_s`, project aspect |
| `narration` | `narrator_text` | OmniVoice: the narrator voice's sample and `sample_text`; ElevenLabs, Google AI: their copy of that voice (7.5) | project `language` |
| `music` | the episode's `music_prompt` | — | minimum length (4.4) |
| `thumbnail` | `{scene_prefix} {thumbnail_prompt}` | references of the 3 characters listed in the most scenes | 16:9, candidate 1–4 |
| `clone_reference_image` | 5.3 § Reference image of a changed asset | — | aspect of its kind |
| `clone_scene_image` | 5.4 § `generating_scene_images` | the original frame of its shot, as the source image | the clone's `aspect` |

A scene with more references than the model takes is made in passes, one reference per pass; Stable
Diffusion WebUI gets one composite image instead (7.1, 7.6).

Clip prompt:

```
{video_prompt}
Character voices: {name}: {voice_description}. {name}: {voice_description}.
Audio: no background music. Keep character dialogue and natural ambient sounds.
```

- `Character voices:` only with `allow_dialogue` and at least one listed character with a voice description.
- The audio line reads `Audio: natural ambient sounds only, no background music, no narration, no
  voiceover.` without `allow_dialogue`, and is left out when `video_prompt` already holds `Audio:` or
  `Music:`. Clips never carry music; the track is mixed in at assembly (4.4).

## Segments

A `scene_clip` longer than the model's clips is made in segments, planned as in 7.1.

- Segment 1 starts from the scene image; segment k from the last frame of segment k − 1, taken with
  `ffmpeg` once that segment is downloaded.
- Each segment's prompt is `Part {k} of {m}. Show {from}-{to}s of this shot.` — followed, from part 2 on, by
  `Continue from the start image.` — then the clip prompt above. `{from}`-`{to}` is the part of the scene's
  clip the segment covers: 0-8, 8-15, 15-22, 22-29, 29-30 for the Google Flow example of 7.1.
- `external_id` is the operation of the segment in flight; each segment is polled on its own, up to 1800 s.
  A retry under § Retries, and an API restart, act on that segment only.
- Files in the scene folder: `clip-segments/{k}.mp4`, its last frame `clip-segments/{k}-last.png`,
  `clip-segments/plan.json` (what the segments are made from — the last bullet) and the join
  `clip-segments/joined.mp4`.
- After the last segment, `ffmpeg` cuts the first second of every segment but the first, joins them in
  order, cuts the result at `clip_duration_s` and writes `clip.mp4`; `clip-segments/` is deleted. A join
  that fails → `failed` with `Joining the clip segments failed: {error}`.
- A request that ends `failed` keeps its segments. The next `scene_clip` of the scene with the same scene
  image, clip prompt, `clip_duration_s`, provider and model starts at the first segment not made; any
  difference deletes them and starts at segment 1.

## Dependencies & resets

| Request | Needs | Manual request refused with | Claimed without it |
|---|---|---|---|
| `scene_image` | every character in `character_ids` has its reference `done` | 409 `Generate the reference images of {names} first` | `failed` — `Reference image missing for: {names}` |
| `edit_image` on a scene | `image_status = done` | 409 `Scene {n} has no image to edit` | — |
| `scene_clip` | `image_status = done` | 409 `Scene {n} has no image yet` | stays `queued` |
| `narration` | non-blank `narrator_text`, a narrator voice | 409 `Scene {n} has no narration text` / `Pick a narrator voice for the project or turn narration off` | — |

| Change | Reset |
|---|---|
| New image — generated, edited or uploaded | clip → `none`, its file and `clip-segments/` deleted; trim back to `1000` / `null` |
| New clip | trim back to `1000` / `null` |
| `narrator_text` changed | narration → `none`, its file deleted |
| `image_prompt`, `video_prompt`, `clip_duration_s` or `character_ids` changed | nothing — the user regenerates |
| On a `done` episode: any reset above, a trim, a scene added, deleted or moved | `needs_assembly = true` |

## Manual edits

Allowed while the episode is `draft`, `paused`, `failed` or `done` and its project is `active`; while
`running` every route below answers 409 `Episode {number} is running — stop it first`.

| Action | Rule | Result |
|---|---|---|
| Add a scene (`afterPosition` absent → at the end, `-1` → first) | fewer than 80 scenes | 400 `An episode holds at most 80 scenes` |
| Add / edit | `image_prompt`, `video_prompt` trimmed 1–4000 characters | 400 `Image prompt must be 1-4000 characters` / `Video prompt must be 1-4000 characters` |
| Add / edit | `narrator_text` at most 1000 characters | 400 `Narration must be at most 1000 characters` |
| Add / edit | `clipDurationS` an integer 4–30; absent on add → the project's `clip_duration_s` | 400 `Clip length must be 4-30 seconds` |
| Add / edit | every id in `characterIds` linked to the project | 400 `Character {id} is not in this project` |
| Move (`position`) | 0 … last | 400 `Position must be between 0 and {last}` |
| Trim | `clip_status = done` | 409 `Scene {n} has no clip yet` |
| Trim | 0 ≤ start < end ≤ clip length, end − start ≥ 1000 ms | 400 `Trim must keep at least 1 s inside the clip` |
| Upload an image | as the reference upload of 4.1 | 400 / 413 as 4.1 |
| Edit image with a prompt | prompt trimmed is 1–2000 characters | 400 `Edit prompt must be 1-2000 characters` |
| Generate, upload, edit, delete | no request of the scene `queued` or `processing` | 409 `Scene {n} has generation running` |
| Any | unknown scene | 404 `Scene {id} not found` |

- A new scene starts with every status `none`. Adding or moving shifts the other positions; deleting closes
  the gap and removes the scene's files.
- Generate image, generate clip and generate narration queue a `scene_image`, `scene_clip` or
  `narration` request with the project's current settings and answer `202`. They also regenerate.
- An uploaded image is `done` at once with `image_source = uploaded`.
