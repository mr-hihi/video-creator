# 4.2 Episodes & script

Part of [4. Film Studio](../4-film-studio.md). An episode is one film of a project, of any length. Its
script is an outline of parts, and each part is written as scenes by its own AI call. The episode runs
through eight stages on its own and pauses at the stop points the user ticked. Episodes keep the story
going: every outline and part call reads the project's story bible (4.1) and the summary of every earlier
episode, and each script rewrites the story bible.

## Data model — `Episode` (table `film_episodes`)

| Field | Type | Meaning |
|---|---|---|
| `id` | string(36) | UUID v4 |
| `project_id` | string(36) | → `film_projects.id`; deleted with the project |
| `number` | int | 1, 2, 3 … per project — `last_episode_number` + 1 at creation, never reused |
| `title` | string(150) | `Episode {number}` until the outline gives one; editable, 1–150 characters |
| `logline` | text \| null | one sentence from the outline |
| `summary` | text \| null | what happens in the episode and where each character stands at its end; written by `updating_story_bible`, editable, at most 10000 characters; sent to the outline and part calls of later episodes |
| `source` | enum | `idea` \| `film_analysis` \| `film_clone` |
| `idea` | text \| null | the user's brief, 1–5000 characters; required for `idea`, optional extra direction for `film_analysis`, not used for `film_clone` |
| `source_job_id` | string(36) \| null | the film analysis job; kept after that job is deleted |
| `source_clone_id` | string(36) \| null | the film clone (domain 5); kept after that clone is deleted |
| `target_duration_s` | int | 8 or more, default 60; the outline splits it into parts (§ `writing_outline`); set at creation for `film_clone` (below) |
| `stop_points` | JSON | `{ "afterOutline", "afterScript", "afterReferences", "afterSceneImages" }` booleans, default `false`, `false`, `false`, `true` |
| `paused_stop_point` | enum \| null | the stage whose stop point the episode last paused at; `Continue` never pauses there again; cleared by `start`, `rewrite-script`, `rewrite-part` and `assemble` |
| `burn_subtitles` | boolean | default `false` (4.4) |
| `subtitle_style` | enum | `clean_white` (default) \| `cinematic_gold` \| `cyber_amber` \| `emerald_hud` |
| `music_prompt` / `thumbnail_prompt` | text \| null | from the outline; editable |
| `music_status` | enum | `none` \| `queued` \| `processing` \| `done` \| `failed` (4.4) |
| `music_path` / `music_error` | string \| null / text \| null | |
| `preset` | JSON | `{ "id", "name", "version" }` of the prompt preset at creation (2.5) |
| `film_outline_prompt` / `film_script_prompt` / `story_bible_prompt` | text | the preset's `filmOutline`, `filmScript` and `storyBible` prompts, copied at creation; `film_outline_prompt` / `story_bible_prompt` are `null` on episodes created before those prompts existed, which then use the code default (2.2) |
| `ai_used` | JSON | the models `writing_outline`, `writing_script` and `updating_story_bible` used (8.1); `{}` before the first runs |
| `status` | enum | `draft` \| `running` \| `paused` \| `done` \| `failed` |
| `step` | enum \| null | the stage running, paused at, or failed; `null` in `draft` |
| `error_message` | text \| null | set when `failed` |
| `needs_assembly` | boolean | `true` when a scene changed after the last assembly (4.3) |
| `video_path` / `subtitles_path` / `thumbnail_path` | string \| null | results (4.4) |
| `duration_ms` | int \| null | length of the assembled film |
| `created_at` / `updated_at` / `started_at` / `finished_at` | datetime (UTC) | |

## Data model — `EpisodePart` (table `film_episode_parts`)

One part of the outline: a stretch of the story written by one AI call.

| Field | Type | Meaning |
|---|---|---|
| `id` | string(36) | UUID v4 |
| `episode_id` | string(36) | → `film_episodes.id`; deleted with the episode |
| `position` | int | 0, 1, 2 … without gaps; shown as `Part {position + 1}` |
| `title` | string(150) | 1–150 characters |
| `plan` | text | 1–5000 characters — what the part tells; its scenes are written from it |
| `target_duration_s` | int | 8–600 — the kept length its scenes should add up to |
| `recap` | text \| null | what happened in the part and where each character stands at its end; written with its scenes (§ `writing_script`); `null` for scenes added by hand or copied from a film clone |
| `created_at` / `updated_at` | datetime (UTC) | |

- A part is *written* once it has a scene. It holds at most 80 scenes (4.3).
- `EpisodeDetail` lists the parts with their counters — `sceneCount`, `imagesDone`, `clipsDone`,
  `narrationDone`, `narrationWithText`, `failedCount` (scenes with an image, clip or narration `failed`),
  `openRequestCount` (requests of its scenes that are `queued` or `processing`) — but not their scenes. `GET /films/parts/{id}` answers `PartDetail` = the part + its scenes + the open
  requests of those scenes.

## Creation

`POST /films/projects/{id}/episodes` — JSON `{ "source", "idea"?, "sourceJobId"?, "sourceCloneId"?, "targetDurationS"?,
"stopPoints"?, "burnSubtitles"?, "subtitleStyle"?, "presetId"? }`.

| # | Rule | Result |
|---|---|---|
| 1 | Captcha token valid (skipped when `CAPTCHA_ENABLED=false`) | 403 `Captcha verification failed` |
| 2 | Project exists | 404 `Film project {id} not found` |
| 3 | Project `active` | 409 `Film project {id} is archived` |
| 4 | `idea` source: `idea` trimmed is 1–5000 characters; other sources: blank or at most 5000 | 400 `Idea must be 1-5000 characters` |
| 5 | `film_analysis` source: `sourceJobId` present | 400 `sourceJobId is required for a film analysis source` |
| 6 | That job exists | 404 `Job {id} not found` |
| 7 | It is one of the three film analysis types (3.1) | 409 `Job {id} is not a film analysis` |
| 8 | It is `done` | 409 `Job {id} is not done` |
| 9 | `targetDurationS` is an integer of at least 8 (not checked for `film_clone`) | 400 `Target duration must be at least 8 seconds` |
| 10 | `presetId` known (optional; default preset when absent) | 400 `Prompt preset {id} not found` |
| 11 | The provider of the `filmScript` model is set up (8.1) | 409 `{provider name} is not set up — open Settings` |
| 12 | `film_clone` source: `sourceCloneId` present | 400 `sourceCloneId is required for a film clone source` |
| 13 | That clone exists | 404 `Film clone {id} not found` |
| 14 | It is `done` (5.1) | 409 `Film clone {id} is not done` |
| 15 | Its `script_language` equals the project's `language` | 409 `The clone is written in {language}; the project narrates in {language}` |
| 16 | Its `aspect` matches the project's `orientation` | 409 `The clone's images are {aspect}; the project is {orientation}` |

- The episode is created `draft`; `number` = the project's `last_episode_number` + 1, which becomes the new
  `last_episode_number`.
- `film_analysis` source: the API copies the job's `character_image_prompts`, `character_voice_prompts`
  and `scene_prompts` rows to `character_image_prompts.md`, `character_voice_prompts.md`,
  `scene_prompts.md`, and its `output/images/` to `images/`, all under
  `storage/films/projects/{project-id}/episodes/{episode-id}/source/`, so deleting the analysis later
  changes nothing.
- `film_clone` source: `target_duration_s` = the clone's scenes × (`clip_duration_s` − 1). In the same
  transaction, so deleting the clone later changes nothing:
  - Every clone asset → a linked library character. A library character whose name equals the asset's
    name — the localized one when changed — case-insensitively, is linked as it is. Otherwise a new one:
    `entity_type` `character`, `location` or `visual_asset` (costume, prop), the asset's description — the
    localized one when changed — the project's `style_id`, `image_prompt` built as 4.1, `origin_clone_id`,
    and the generated reference (changed) or the `reference_frame` (unchanged) copied as its reference:
    `done`, `reference_source = film_clone`; no reference → `none`.
  - The clone scenes fill parts of 80 in order: part k holds clone scenes 80(k − 1) + 1 … 80k, with `title`
    = `Part {k}`, `plan` = `Scenes {from}-{to} of the film clone.`, `target_duration_s` = its scenes ×
    (`clip_duration_s` − 1), kept without the 8–600 check, and `recap` = `null`.
  - Every clone scene → a scene in its part, in order: `image_prompt` = the clone scene's, `video_prompt` =
    its `description` followed by `Dialogue: {dialogue}` when set, cut to 4000 characters, `narrator_text` =
    `null`, `character_ids` = the characters of its assets, the image copied — `image_status = done`,
    `image_source = film_clone`, `trim_start_ms` = 1000, `clip_duration_s` = the project's.

## Stages

| # | `step` | Work | Ends when |
|---|---|---|---|
| 1 | `writing_outline` | one call of the episode's AI model writes the title, logline, parts, music prompt and thumbnail prompt (below); skipped when the episode already has parts — added by the user, kept from an earlier run, or copied from a film clone | the parts are saved |
| 2 | `writing_script` | one call per part without scenes, in `position` order, writes its scenes, its recap and any new characters (below) | every part has scenes |
| 3 | `updating_story_bible` | one call writes the episode's `summary` and the project's new `story_bible` (below) | both are saved |
| 4 | `generating_references` | queues a `character_image` request for every character a scene lists whose reference is `none` or `failed` | those references are final |
| 5 | `generating_scene_images` | queues a `scene_image` request for every scene whose image is `none` or `failed` | every scene image is final |
| 6 | `generating_clips` | queues a `scene_clip` request for every scene whose clip is `none` or `failed` | every clip is final |
| 7 | `generating_audio` | queues narration and music (4.4) | they are final |
| 8 | `assembling` | builds the MP4 and `.srt` (4.4) | the files are written |

- A stage with nothing to queue ends at once.
- A generation stage (4–7) fails when one of its requests ends `failed`. It waits until none of its
  requests is `queued` or `processing`, then the episode becomes `failed` with `step` = that stage and
  `error_message` = `{n} {item}(s) failed — fix them and resume`, `{item}` being `reference image`,
  `scene image`, `clip`, `narration` or `music track`; when narration and music both fail, the two counts are
  joined with `and` (`2 narration(s) and 1 music track(s) failed — fix them and resume`).
- `writing_outline`, `writing_script`, `updating_story_bible` and `assembling` run one episode at a time in
  the batch worker of 1.1, between jobs, like Film Clone's AI steps; the generation stages move on as soon as
  a request of the episode becomes final.
- `writing_outline`, `writing_script`, `updating_story_bible` and `assembling` fail with their own messages
  (below, 4.4).

## Status workflow

```
draft ──Start──▶ running ──stage ends at a ticked stop point──▶ paused ──Continue──▶ running
                   │ ├──last stage ends──▶ done ──Assemble──▶ running (stages 5–6)
                   │ └──a stage fails──▶ failed ──Resume──▶ running
                   └──Stop──▶ paused
```

| Action | Allowed from | Effect |
|---|---|---|
| `start` | `draft` | runs from `writing_outline` |
| `continue` | `paused` | runs from `step`; never pauses again at the stop point it was paused at |
| `resume` | `failed` | runs from `step`, queuing only what is `none` or `failed`; `writing_script` writes only the parts without scenes |
| `stop` | `running` | `paused` at once, `step` kept; the episode's `queued` requests become `cancelled`; `processing` ones finish — a submitted generation cannot be called back and is already paid; a `writing_outline`, `writing_script`, `updating_story_bible` or `assembling` in progress stops — its `claude` or ffmpeg process is killed; a Gemini call (8.4) cannot be called back and runs out — and its result is dropped; `Continue` runs that step again, and `writing_script` keeps the parts it already wrote |
| `assemble` | `done` | runs `generating_audio` (only what is missing) then `assembling` |
| `rewrite-script` | `draft`, `paused`, `failed`, and no scene has an image or a clip | deletes the parts and scenes and runs from `writing_outline` |
| `rewrite-part` (`POST /films/parts/{id}/rewrite`) | `paused`, `failed`, `done`, and no scene of the part has an image or a clip | deletes the part's scenes and recap and runs from `writing_script`, which writes that part and any other part without scenes |

| Rule | Result |
|---|---|
| Action not allowed from the current status | 409 `Cannot {action} episode {number} while it is {status}` — `{action}` is `start`, `continue`, `resume`, `stop`, `assemble`, `rewrite the script of` or `rewrite a part of` |
| `start` / `continue` / `resume` / `assemble` / `rewrite-part` with `allow_narration` and no narrator voice | 409 `Pick a narrator voice for the project or turn narration off` |
| `rewrite-script` with a scene image or clip | 409 `Scenes already have images or clips — delete them before rewriting` |
| `rewrite-part` with an image or clip on a scene of the part | 409 `Part {k} already has images or clips — delete them before rewriting` |
| `rewrite-script` / `rewrite-part` while a request of the episode is `queued` or `processing` | 409 `Episode {number} has generation running` |
| Any action on an archived project | 409 `Film project {id} is archived` |
| Unknown episode | 404 `Episode {id} not found` |
| Unknown part | 404 `Part {id} not found` |

- Stop points: after `writing_outline` (`afterOutline`), after `writing_script` (`afterScript` — before the
  story bible is updated, so the bible reads the scenes as the user left them), after
  `generating_references` (`afterReferences`), after `generating_scene_images` (`afterSceneImages`).
  Reaching one → `paused`, `step` = the stage just finished. A stage that ends at once — `writing_outline`
  skipped because the episode has parts, a generation stage with nothing to queue — still pauses at its stop
  point.
- While `running`, every scene edit and every generation on the episode answers 409 `Episode {number} is
  running — stop it first`. In the other statuses the user edits and generates scene by scene (4.3).
- `done` is final until a scene or the order of the parts changes: `needs_assembly` becomes `true` and
  `Assemble` builds the film again.
- API restart: a `running` episode stays `running`; its requests resume as in 4.3; an interrupted
  `writing_outline`, `writing_script`, `updating_story_bible` or `assembling` runs again, and
  `writing_script` keeps the parts it already wrote.
- Characters created by a script stay in the library and linked after `rewrite-script` and `rewrite-part`.

### Edit and delete

| Field (`PATCH`) | When |
|---|---|
| `title` | any status except `running` |
| `idea`, `targetDurationS` | `draft` only — rules 4, 9 |
| `stopPoints` | any status |
| `burnSubtitles`, `subtitleStyle` | any status except `running`; on `done` → `needs_assembly = true` |
| `musicPrompt` | any status except `running`; resets the music track to `none`, and on `done` → `needs_assembly = true` |
| `thumbnailPrompt` | any status except `running` |
| `summary` | any status except `running` |

| Rule | Result |
|---|---|
| A field other than `stopPoints` while `running` | 409 `Episode {number} is running — stop it first` |
| `idea` or `targetDurationS` outside `draft` | 409 `Idea and target length can change only before the episode starts` |
| `summary` over 10000 characters | 400 `Summary must be at most 10000 characters` |

Delete: refused while a request of the episode is `queued` or `processing` — 409 `Episode {number} has
generation running`. Removes its parts, scenes, requests and folder; other episodes keep their numbers.
The story bible keeps what the episode added to it.

### Parts

Allowed while the episode is `draft`, `paused`, `failed` or `done` and its project is `active`; while
`running` every route below answers 409 `Episode {number} is running — stop it first`.

| Action | Rule | Result |
|---|---|---|
| Add (`POST /films/episodes/{id}/parts`; `afterPosition` absent → at the end, `-1` → first) / edit (`PATCH /films/parts/{id}`) | `title` trimmed 1–150 characters | 400 `Part title must be 1-150 characters` |
| Add / edit | `plan` trimmed 1–5000 characters | 400 `Part plan must be 1-5000 characters` |
| Add / edit | `targetDurationS` an integer 8–600 | 400 `Part length must be between 8 and 600 seconds` |
| Move (`position` in `PATCH`) | 0 … last | 400 `Position must be between 0 and {last}` |
| Delete (`DELETE /films/parts/{id}`) | the part has no scene | 409 `Part {k} has scenes — delete them first` |
| Any | unknown part | 404 `Part {id} not found` |

- Adding, moving or deleting shifts the other positions. A moved part takes its scenes with it; on a `done`
  episode → `needs_assembly = true`.
- A part without scenes is written the next time `writing_script` runs — a `start`, a `continue` or
  `resume` at that step, or `rewrite-part` on it.
- Editing a written part's title, plan or length changes no scene — the user rewrites the part.

## Context sent to the AI model

Every `writing_outline` and `writing_script` call of an episode carries the same context lines, written by
the app:

- `Series: {name}` and `Premise: {description}` when set.
- `Story bible:` and the project's `story_bible`, when set.
- `Language of narration and dialogue: {Vietnamese | English | Japanese}`.
- `Earlier episodes:` — for every earlier episode of the project with a script, `{number}. {title} —
  {logline}`, then `Summary: {summary}` when set.
- `idea` source: `Episode idea:` and the idea.
- `film_analysis` source: `Adapt this film analysis:` with the copied character image prompts, character
  voice prompts and scene prompts under their headings; `Extra direction:` and the idea when set.

## `writing_outline`

- One call of the `filmScript` model (8.1, 8.2) with a JSON schema, limited to `FILM_SCRIPT_TIMEOUT_SEC`.
- System prompt: the episode's `film_outline_prompt`.
- User message, written by the app (shown read-only in the preset editor, 2.2): the context above, then
  - `Split the episode into parts whose lengths add up to about {target_duration_s}s. Each part lasts 8-600
    s.`
  - `Cast:` — every linked character as `{name} ({entity_type}): {description}`.
- Output shape (the schema): `title`, `logline`, `parts[] { title, plan, durationS }`, `musicPrompt`,
  `thumbnailPrompt`.

The reply is untrusted input:

1. Drop parts with a blank `title` or `plan`; cut titles to 150 characters and plans to 5000.
2. `durationS` rounded to an integer and kept within 8–600; missing or not a number → 600.
3. `title` blank → `Episode {number}`; cut to 150 characters.
4. Trim `logline`, `musicPrompt` and `thumbnailPrompt`; blank → `null`.

Parts are saved at positions 0 … n − 1 with `recap` = `null`. A failing call fails the stage with the
messages of 8.2. No part left after step 1 fails it with `{ai} returned no parts`.

## `writing_script`

- One call of the `filmScript` model (8.1, 8.2) per part without scenes, in `position` order, each with a
  JSON schema and limited to `FILM_SCRIPT_TIMEOUT_SEC`. Each part is saved when its call ends, so a later
  part reads the recap and the characters of the earlier ones.
- System prompt: the episode's `film_script_prompt`.
- User message, written by the app (shown read-only in the preset editor, 2.2): the context above, then
  - `Frame: 16:9 landscape` or `Frame: 9:16 portrait`; `Style: {style name} — {style_instruction}`.
  - `Write scenes whose clip lengths, each minus its first second, add up to about {target_duration_s}s.
    Give each scene the clip length its action needs, 4-30 s; a typical clip lasts {clip}s. The first second
    of every clip is cut, so a scene's narration must fit in its clip length minus 1 s.` —
    `{target_duration_s}` is the part's, `{clip}` the project's `clip_duration_s`.
  - `Characters may speak inside clips.` or `No character speaks; clips carry ambient sound only.`
  - `Narration: on` or `Narration: off — leave narratorText empty.`
  - `Cast:` — every linked character as `{name} ({entity_type}): {description}. Voice: {voice_description}`,
    then `Reuse these names exactly. Add a character only when the story needs one.`
  - `Episode outline:` — `{k}. {title}: {plan}` for every part, then `Write part {k} now.`
  - `Story so far:` — for every earlier part of the episode, `{k}. {recap}`, or `{k}. {plan}` when it has no
    recap; left out for the first part.
  - `film_analysis` source: `Reference frames:` with one copied frame file name per line.
- Output shape (the schema): `recap`, `characters[] { name, entityType, description, voiceDescription,
  referenceFrame }`, `scenes[] { imagePrompt, videoPrompt, narratorText, characterNames[], durationS }`.
  `referenceFrame` is a frame file name or `null`.

### Normalising the reply

The reply is untrusted input:

1. Drop scenes with a blank `imagePrompt` or `videoPrompt`; keep the first 80.
2. `durationS` rounded to an integer and kept within 4–30; missing or not a number → the project's
   `clip_duration_s`.
3. Trim `narratorText`; blank → `null`.
4. For each `characters[]` entry with a non-blank name, matched case-insensitively:
   - a linked character → kept as is;
   - a library character not linked → linked;
   - otherwise a new library character: `entityType` (unknown → `character`), `description` (blank → the
     name), `voiceDescription`, the project's `style_id`, `image_prompt` built as 4.1, `origin_job_id` =
     `source_job_id`.
5. `referenceFrame` naming a copied frame, for a character whose reference is `none` → that frame becomes
   its reference: `done`, `reference_source = film_analysis`.
6. Resolve each scene's `characterNames` against the cast, case-insensitively; drop unknown names and
   repeats.
7. Trim `recap` and cut it to 5000 characters; blank → `null`.

Scenes are saved in the part at positions 0 … n − 1, every status `none`, `trim_start_ms` = 1000,
`clip_duration_s` from step 2 (4.3).

A failing call fails the stage with `error_message` = `Part {k}: {message of 8.2}`; the parts after it are
not written. No scene left after step 1 fails it with `Part {k}: {ai} returned no scenes`.

## `updating_story_bible`

- One call of the `filmScript` model (8.1, 8.2) with a JSON schema, limited to `FILM_SCRIPT_TIMEOUT_SEC`,
  each time the stage runs — after the first script, a `rewrite-script` or a `rewrite-part`.
- System prompt: the episode's `story_bible_prompt`.
- User message, written by the app (shown read-only in the preset editor, 2.2):
  - `Series: {name}` and `Premise: {description}` when set.
  - `Language of narration and dialogue: {Vietnamese | English | Japanese}`.
  - `Current story bible:` and the project's `story_bible`, or `Current story bible: (empty)`.
  - `Episode {number}: {title} — {logline}`.
  - `Parts:` — for each part, `{k}. {title}` then its `recap`; a part without a recap — added by hand or
    copied from a film clone — gives its scenes instead, one line each: `Scene {n}: {video_prompt}`,
    followed by ` Narration: {narrator_text}` when set.
  - `Keep the story bible under 20000 characters.`
- Output shape (the schema): `summary`, `storyBible`.

The reply is untrusted input:

1. Trim both.
2. `summary` cut to 10000 characters; blank → `null`.
3. `storyBible` blank fails the stage with `{ai} returned an empty story bible`; over 20000 characters with
   `{ai} returned a story bible over 20000 characters`.

One transaction saves the episode's `summary` and the project's `story_bible`, `story_bible_episode_id` =
the episode and `story_bible_updated_at` = now. A failing call fails the stage with the messages of 8.2;
`resume` runs it again.
