# Business documentation — video-tool

Business specifications for video-tool. Each file under `business/` documents one domain; test cases
live under `test-cases/` with the same file name.

## Domains

| # | Domain | Document | Scope |
|---|---|---|---|
| 1 | Video to Markdown | [1-video-to-markdown.md](./business/1-video-to-markdown.md) | `Job` lifecycle and per-type steps (1.1) + uploaded-file source with whisper transcription (1.2) + YouTube-link source — link parsing, metadata check at creation, video-only download (1.3) + transcript from YouTube captions — manual over auto, no machine translation (1.4) + key moments picked by the job's AI model with its `videoToMarkdown` prompt, and frame capture (1.5) + Markdown layout, YouTube source link and timestamp links (1.6) + header menu, home with prompt preset select and job-detail screens (1.7) |
| 2 | Prompt Presets | [2-prompt-presets.md](./business/2-prompt-presets.md) | Named sets of the eleven AI model prompts — video → Markdown, character image, character voice, scene, film outline, film script, story bible, clone assets, clone shots, clone localization, clone script — with versions, 20 kept (2.1) + default text and the read-only parts the app adds (2.2) + validation, default mark, delete rules (2.3) + duplicate, JSON export / import, older files accepted with defaults for missing prompts (2.4) + prompt copy into each job, film clone and Film Studio episode at creation (2.5) + `Prompt override` tab of `/settings` with history and restore (2.6) |

| 4 | Film Studio (split) | [4-film-studio.md](./business/4-film-studio.md) | AI films as series, ported from flowkit, images from Google Flow, an API provider or a local model and clips from Google Flow or an API provider, per project: projects with a story bible the AI model rewrites after each episode's script, shared character library, styles, voice templates (4.1) + episodes of any length from an idea, a film analysis or a film clone, eight stages with stop points, an outline of parts of up to 600 s and 80 scenes written by the `filmOutline` prompt, each part's scenes and recap written by the `filmScript` prompt, the episode summary and story bible written by the `storyBible` prompt, part edits and rewrites (4.2) + scenes with clips of 4–30 s, generation queue and worker, retries, prompts sent, long clips joined from segments, resets, manual edits (4.3) + narration, music looped to the film's length, `ffmpeg` assembly with a time limit per command, subtitles, thumbnails (4.4) + `/films`, project with the `Story bible` tab and the episode popup, episode screen with the outline, library screens (4.5) |

| 6 | Settings | [6-settings.md](./business/6-settings.md) | App-wide settings as `AppSetting` key / value rows with defaults — the Film Clone script language, the AI models, the input modes of the jobs and of Film Clone, and the image and clip providers Film Clone and Film Studio pick over the shared routes (6.1) + `/settings` screen: tabs `General`, `AI models`, `Prompt override`, `Film Clone`, `Film Studio`, one `Save` per tab and `PATCH /settings/ai-models` saving all or none (6.2) |

| 8 | AI Models | [8-ai-models.md](./business/8-ai-models.md) | One model for all AI steps plus a model per step group — key moments, film analysis, film script, film clone — from Claude CLI, Gemini or OpenAI, read when each call starts, the input mode copied at creation — `filmCloneInputMode` for Film Clone, `inputMode` for the other jobs, 409 when a provider has no key, the model each step used kept in `ai_used` (8.1) + calling the Claude CLI, the Gemini API and the OpenAI API, images scaled to 480 px for every provider, answers, failures without retry, limits, `aiActivity` (8.2) + picking key moments from the transcript or from the transcript and one frame per second, in windows sized to the provider (8.3) + the `Text` group of the `AI models` tab with `Apply to all steps` and the input mode, the `AI` line on the forms and per step on detail screens (8.4) |

## Conventions

- File name: `{N}-{slug}.md`. One file per domain.
- Sections inside a file are numbered `{N}.{i}`.
- API endpoints, configuration, capacities and non-goals close each domain file.
- A new feature of an existing domain is a new section in that file, not a new file.
- A spec describes the current behaviour. The reason for a change goes in the commit message.
